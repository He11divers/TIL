# Dong-H-LEE 노션 학습 기록 이관

이 저장소에서 Dong-H-LEE의 학습 기록을 옮길 때 사용한다. 경로는 저장소 루트 기준이며, 현재 사용자의 명시적 요청을 우선한다.

## 작성 범위와 입력

- 먼저 [README.md](../../../README.md)의 작성 규칙과 대상 폴더의 기존 파일, Git 변경 상태를 확인한다.
- 글과 이미지는 `raw/Dong-H-LEE/` 안에서만 작성·수정한다. 다른 스터디원의 파일이나 사이트 코드는 이관 작업에 포함하지 않는다.
- 지침·스킬 파일은 게시글로 읽히지 않도록 `raw/` 밖에 둔다. 일반 이관 요청은 이 설정 파일을 수정하는 요청이 아니다.
- 사용자가 지정한 페이지, 토글 또는 구간과 저장 폴더·파일명을 따른다. 공백도 경로의 일부로 보존한다. `System Programming/`과 `SystemProgramming/`을 임의로 바꾸거나 합치지 않는다.
- 저장 위치가 생략되면 기존 주제별 구조에서 분명한 위치를 선택한다. 범위나 목적지가 여러 가지로 해석될 때만 필요한 정보를 확인한다.
- “보여?”, “접근 가능해?”는 접근 확인 요청이다. 본문·이미지 접근 상태만 확인하고 파일을 생성하지 않는다.
- 기존 글의 갱신 요청이면 그 글과 관련 이미지에 필요한 변경만 적용한다. 새 글과 이름이 충돌하면 먼저 기존 내용을 확인하고, 무관한 기록을 덮어쓰지 않는다.

## 노션에서 원문 가져오기

1. 현재 연결된 Notion 도구의 페이지 조회 기능을 우선 사용한다. `app.notion.com/p/...` 링크도 페이지 ID로 조회할 수 있다.
2. 응답의 잘림·미지원 블록 표시를 확인한다. 선택한 범위에 누락이 있으면 추가 조회로 확보하고, 해결되지 않은 부분은 사용자에게 알린다.
3. Notion 전용 Markdown 구문을 해석해야 하면 조회 도구의 문서나 `notion://docs/enhanced-markdown-spec`을 읽는다.
4. “2주차 토글 내부”처럼 지정되면 그 토글의 자식 내용만 추출한다. 인접 주차, 페이지 속성, 상위 강의 정보는 섞지 않는다. 다른 페이지를 링크했다는 이유만으로 그 페이지까지 이관하지 않는다.
5. 연결된 도구로 원문이나 이미지를 가져올 수 없으면 접근 가능한 전달 방식으로 이어간다. 사용자가 내보낸 Markdown & CSV ZIP을 제공한 경우 그 안의 Markdown과 첨부 이미지를 사용한다. 확인하지 못한 내용을 추정해서 채우지 않는다.

## 본문 보존과 Markdown 변환

- 문구, 오탈자, 수식의 값, 코드, 강조, 목록 순서, 표, 이미지 위치와 캡션을 보존한다. 별도 요청 없이 요약·교정하거나 설명을 추가하지 않는다.
- 변경은 Markdown으로 표현하기 위한 구문·공백 조정, 필수 frontmatter 추가, 이미지 경로 치환으로 제한한다.
- 선택한 토글 바깥쪽 들여쓰기를 제거하고 내부 목록의 계층은 유지한다. 제목·문단·목록·이미지 사이에 필요한 빈 줄을 넣어 목록이나 본문이 코드 블록으로 바뀌지 않게 한다.
- `<empty-block/>`은 빈 줄로 바꾸고, 노션 조회 응답의 메타데이터와 전용 블록 속성은 게시글 본문에 남기지 않는다. 이스케이프 문자의 화면상 의미를 보존한다.
- 사이트의 Markdown 뷰어는 raw HTML을 건너뛴다. 노션의 토글·열·콜아웃 같은 구조는 내용을 유지하는 GFM 제목·목록·인용문 등으로 옮긴다. 중요한 표현을 보존할 수 없으면 그 한계를 알린다.

## Frontmatter

- `title`과 `date: "YYYY-MM-DD"`는 필수이며, 제목과 선택적 `description`은 비어 있지 않은 문자열이어야 한다. YAML 특수문자가 들어갈 수 있는 문자열은 인용한다.
- 제목은 사용자가 지정한 제목을 우선하고, 없으면 대상 구간의 제목이나 파일명에서 정한다.
- 날짜는 사용자가 지정한 날짜 또는 원문에 명시된 학습 날짜를 사용한다. 기존 글을 갱신하면 별도 요청 없이 날짜를 바꾸지 않는다.
- 페이지의 최종 수정 시각이나 스크린샷 파일명만으로 학습 날짜를 확정하지 않는다. 날짜가 불분명하면 확인하고, 답변을 기다리는 동안 원문 확보 등 날짜에 의존하지 않는 작업을 진행한다.
- 불필요한 요약을 만들기 위해 `description`을 추가하지 않는다.

## 이미지 저장

- 선택한 내용에 포함된 이미지는 원본 데이터를 다운로드하여 모두 `raw/Dong-H-LEE/images/`에 저장한다. 외부 이미지도 가능한 경우 같은 방식으로 로컬에 저장한다.
- 노션의 서명된 임시 이미지 URL을 게시글 링크로 남기지 않는다. 다운로드할 때 만료되었다면 원문을 다시 조회해 URL을 갱신한다. 새 URL로도 실패하면 실패한 이미지를 알리고 내보내기 파일 등으로 보완한다.
- 이름은 기존 파일과 충돌하지 않게 정한다. 예: `20260908_system_programming_bits_01.png`. 날짜가 확정되지 않았으면 날짜를 추정해 파일명에 넣지 않는다.
- 같은 이미지를 여러 곳에서 참조하면 하나의 파일을 재사용할 수 있지만 본문에서 참조한 위치는 모두 유지한다. 기존 이미지는 동일한 파일인지 확인한 경우에만 재사용한다.
- README가 지원하는 이미지 확장자를 사용하고 실제 형식과 일치시킨다. 다운로드 실패 응답이나 HTML을 이미지 확장자로 저장한 채 완료 처리하지 않는다.
- 링크는 이미지가 아니라 **Markdown 파일이 있는 폴더**를 기준으로 계산한다. 공백이 있는 링크 경로는 Markdown에서 유효하게 표현한다.

예를 들어 `raw/Dong-H-LEE/System Programming/2-1.Bits.md`에서는 다음처럼 연결한다.

```md
![](../images/20260908_system_programming_bits_01.png)
```

원문에 이미지 캡션이 있으면 함께 보존한다. 캡션이 없는 이미지에 임의의 설명을 본문으로 추가하지 않는다.

## 검증과 전달

- 선택한 원문의 문구·항목·이미지 순서와 결과물을 대조한다. 변환용 공백·구문·이미지 경로 외에 빠지거나 바뀐 내용이 없는지 확인한다.
- 필수 frontmatter와 실제 날짜를 검증한다.
- 모든 로컬 이미지 참조가 존재하는 파일로 연결되고 `raw/Dong-H-LEE/images/` 내부로 해석되는지 확인한다. 파일이 비어 있지 않고 정상 이미지인지도 검사한다.
- Git 변경 상태를 확인하여 이관 결과가 `raw/Dong-H-LEE/` 안에만 있는지 확인한다. 작업 전에 있던 사용자 변경은 보존한다.
- TIL 작성만으로는 의존성 설치, Next.js 서버 실행, 전체 빌드가 필요하지 않다. 미리보기 요청이나 표현상 문제가 있을 때 필요한 범위로 확인한다.
- 결과 파일 링크, 저장한 이미지 수, 사용한 날짜와 미해결 사항을 간결하게 보고한다. 확인하지 않은 사이트 렌더링을 검증했다고 말하지 않는다.
- 글 작성 요청만으로 commit·push하지 않는다. 사용자가 요청하면 대상 파일만 stage하고 README의 커밋 형식과 `main` 직접 반영 방식을 따른다.
