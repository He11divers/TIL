#### References

![](../images/20261022_c_sw_week4_3_26.png)

- reference는 pointer와 유사하게 사용될 수 있음.
- pointer보다 less powerful하지만 더 안전한 문법임
- int\* pa = &a; → pa에게 할당된 stack에는 a가 저장된 주소가 저장되어 있음.
- \*pa = 20; 하면 pa가 가리키고 있는 a가 저장된 메모리의 값을 20으로 바꾸는거니까 a=20;이 됨.
- int& rb = b; → rb는 b의 alias처럼 사용함.
- rb = 20; → rb와 b는 값을 공유한다고 보면 됨. → b도 20임 됨.

![](../images/20261022_c_sw_week4_3_27.png)

- 사용이 편해진만큼 포인터에 비해 reference에는 제약 조건이 좀 생김.
- 포인터는 초기화를 하지 않아도 됨. → 하지만 reference는 초기화를 해야함.

![](../images/20261022_c_sw_week4_3_28.png)

- 포인터는 NULL 값을 가질 수 있음 → 하지만 reference는 NULL을 참조할 수 없음.

![](../images/20261022_c_sw_week4_3_29.png)

- Read-only parameter를 넘길 때 const Point\* p를 넘길 때랑 const Point& p를 넘길 때 어셈블리 컴파일러에서는 완전히 동일함.
- 단, 포인터를 사용하면 p→x=3으로 함수 호출 / 참조를 사용하면 p.x=3으로 사용

![](../images/20261022_c_sw_week4_3_30.png)

- TestConstReference의 parameter들은 전부 const니까 전부 compile error가 뜬다.
- main에 있는 메모리를 전부 카피해서 할당하지 않으려면 포인터 혹은 참조를 사용해서 넘기면 된다는 정도만 알고 넘어가자.

![](../images/20261022_c_sw_week4_3_31.png)

![](../images/20261022_c_sw_week4_3_32.png)

- NULL이 parameter로 넘겨지면 pt→b = 20을 실행할 때 SEGFAULT가 생김.

![](../images/20261022_c_sw_week4_3_33.png)

- 레퍼런스는 동적 할당에서는 사용할 수 없음. → 이미 존재하는 값에 대한 참조이기 때문.

![](../images/20261022_c_sw_week4_3_34.png)

- Address-of operator로 사용되는 ‘&’는 &a로서 “a라는 변수의 주소”라는 의미를 가지고 있음.
  → & + \[variable name\]

  → \[type name\] + &
