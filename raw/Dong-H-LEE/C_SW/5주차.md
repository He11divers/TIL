#### Compilation

![](../images/20261022_c_sw_week5_01.png)

![](../images/20261022_c_sw_week5_02.png)

- .c 코드를 compile해서 object 코드로 바꾼다. = source 코드의 정의를 기계어로 바꾼다.
- Linking는 따로 따로 떨어져 있는 기계어 함수는 하나의 실행파일로 묶는 행위를 말한다.

![](../images/20261022_c_sw_week5_03.png)

- Compile 하려면 함수의 선언을 알아야 한다.
- ‘ # ‘ 은 math.h에 대한 내용이 파일의 content로 통째로 갈아끼워진다.
- 컴파일러는 위에서 아래로 코드를 단 한번만 읽는다. → 위 코드를 읽고 있다면 아래 코드에 뭐가 나오는지 컴파일러는 알고 있지 않음.

![](../images/20261022_c_sw_week5_04.png)

- C++의 헤더에는 함수의 선언, struct 혹은 class의 정의(함수의 정의는 안됨) enum, macro, inline 함수들이  들어간다.
- 공통점으로는 컴파일러가 사용하는 정의임 → 실행파일에는 들어가지 않음.

![](../images/20261022_c_sw_week5_07.png)

- main.c에서 #include “point.h” 로 struct가 1번 정의됨.
- 이후 #include “pointfunc.h”를 통해 다시 #include “point.h”가 한번 더 정의됨.
- 그래서 compile error가 발생한다. → 하나의 source code에 같은 구조체가 2번 정의됨.
- 해결법.
  1. pointfunc.h에 #include 제외. → 단, 이 경우에는 #include의 순서가 중요함. main에서 point.h에 대한 include가 pointfunc.h의 include에 우선되어야함.
  2. point.h 파일의 가장 처음에 #pragma once를 삽입

![](../images/20261022_c_sw_week5_11.png)

- #pragma once : 한 source code를 compile하는 중에 첫 번째 include는 통과 2번째부터는 다시 정의하지 말고 무시하고 지나가라는 의미의 guard
- 근데 이건 공식적인 방법은 아니지만 범용적으로 다 쓰일 수 있긴 함.

![](../images/20261022_c_sw_week5_12.png)

- 모든 헤더 파일에 #pragma once 박기.

![](../images/20261022_c_sw_week5_13.png)

- #pragma once 말고도 #ifndef라는게 있음 → if not defined

```c++
#ifndef __POINT_H__  //만약 __POINT_H__라는게 선언되어 있지 않다면 아래로 들어감.
										 //선언되어 있다면 아래로 들어가지 않고 넘어감.
#define __POINT_H__ 
```

#### Inline Function

![](../images/20261022_c_sw_week5_14.png)

![](../images/20261022_c_sw_week5_15.png)

- inline function 정의부는 compiler가 실행파일에 바로 적지 않고 메모리에 저장해둠.
- 이후 inline 함수를 실행하는 순간이 올 때 함수 자리에 코드가 불려와서 박힘.
- 장점 : 실행이 빠름.
- 단점 : inline 함수가 자주 사용된다면 main 함수의 obj가 매우 커질 수 있음.

![](../images/20261022_c_sw_week5_16.png)

- inline은 class에서도 사용됨.
- Header 파일에 class가 존재하는데 class 내부에 함수가 선언이 아니라 정의되어 있다면 자동으로 inline화 됨. → 헤더에는 정의되면 안되니까

![](../images/20261022_c_sw_week5_17.png)

- Macro 정의에서는 모든 argument를 괄호로 감싸 주어야함.
