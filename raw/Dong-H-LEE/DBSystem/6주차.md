#### SELECT Operation

→ 여러 개의 data 중 원하는 조건에 맞는 data를 SELECT 해서 가져오는 Operation

![](../images/20261011_dbsystem_week6_05.png)

- Format → 

    ![](../images/20261011_dbsystem_week6_06.png)

    → R이라는 이름을 가지는 table에서부터 selection condition(조건)에 맞는 데이터를 select 하라는 의미

![](../images/20261011_dbsystem_week6_07.png)

- Meaning
    - relation R로 부터 selection condition에 맞는 tuple들을 선택한 subset.
    - Selection Condition C는 Boolean expression의 형태로 표현됨.
        1. \<attribute name\> \<comparison op\> \<constant value\>
        2. \<attribute name\> \<comparison op\> \<attribute name\>
    - 선택된 tuple들의 집합도 relation이 됨. → r(R)은 c라는 조건을 만족하는 t들이 구성요소가 되는 table.

#### PROJECT Operation

![](../images/20261011_dbsystem_week6_09.png)

- Table R에 있는 Tuple 들의 attribute value들을 다 보여주는게 아니라 \<attribute list\> 에 있는 값만 보여줘라(PROJECT 해라)

    → attribute list에 있는 측면으로만 PROJECT 하라는 의미.

- 결과로 나타나는 Tuple은 기본적으로는 원래 있었던 Tuple과 같다 → 기본적으로는? 그렇지 않을 때도 있나??

![](../images/20261011_dbsystem_week6_10.png)

- PROJECT Operation은 table R로 부터 attribute list L에 나타난 columns(attribute)만을 골라서 보여달라는 것을 의미.
- 결과로 나타나는 table은 L에 나타난 attribute value만을 가지는 tuple이 나옴.
- 원래 Tuple이 100개라면 기본적으로 결과로 나오는 Tuple도 100개임. 하지만 실제로는 Tuple의 수가 줄어들 수 있음.  
  → PROJECT Operation의 결과는 100개 중에 중복된 것이 있다면 그 중 하나만을 표현함.  
  → 전체 attribute에서는 distinct지만, L에 대해서는 중복된게 존재할 수 있다.

![](../images/20261011_dbsystem_week6_11.png)

![](../images/20261011_dbsystem_week6_12.png)

→ 중복된 것을 제거해서 tuple의 수가 줄어들었음.

#### Union Compatibility

→ 합집합 호환성 or 타입 호환성

![](../images/20261011_dbsystem_week6_20.png)

- 2개의 relation이 유의미한 Union이 되기 위한 조건이 있다는 의미.
- 아래 2 조건은 합집합, 교집합, 차집합 3가지에 모두 적용되는 조건임.
- 조건 1) 2개의 relation이 Union 되기 위해서는 2개의 relation의 attribute 수가 같아야함.

  → attribute의 이름은 달라도 됨. domain이 완전히 같지 않아도 됨..그래서 애매하게 표현한 것..

#### CARTESIAN PRODUCT Operation

→ 곱집합. 

![](../images/20261011_dbsystem_week6_26.png)

- 2개의 Table에 대해서 하나의 Table이 나오는데, 만들어질 수 있는 모든 조합이 나옴.

![](../images/20261011_dbsystem_week6_27.png)

- 동일하게 새로운 Table이 생성됨.
- 왼쪽에 존재하는 하나의 Table에 존재하는 각 tuple과 반대쪽에 있는 각 tuple을 모든 경우의 수로 combine한 결과가 나옴.
- Result의 attirbute 수 : n + m
- Result의 tuple 수 : A의 tuple 수 \* B의 tuple 수
- CARTESIAN PRODUCT 자체만으론느 별 의미가 없음 → result 이후 selection을 진행했을 때 의미가 생김.

![](../images/20261011_dbsystem_week6_28.png)

- 각 여성 사원의 부양가족의 이름을 알고 싶은 상황.
- EMPLOYEE에서 Female을 갖는 tuple을 SELECT → FEMALE_EMPS relation 생성
- FEMALE_EMPS를 대상으로 이름(성,이름) , 주민번호를 PROJECT → EMPNAMES
- EMPNAMES \* DEPENDENT → 여성 EMPLOYEE와 모든 DEPENDENT의 조합 생성 → EMP_DEPENDENTS
- 근데 cartesian의 결과는 모든 가능한 조합이니까 Ssn = Essn(누구의 부양가족인지)이 맞는 tuple만 SELECT → ACTUAL_DEPENDENTS  
  **→ 서로 다른 table에 있는 tuple 간의 올바른 관계를 찾아내는 가장 중요한 작업**

- 제대로 조합된 ACTUAL_DEPENDENTS에서 PROJECT를 통해서 결과 도출

#### THETA JOIN Operation(세타 조인)

![](../images/20261011_dbsystem_week6_36.png)

- Table R 과 Table S의 조합 중 join condition에 맞는 조합만을 찾는 JOIN Operation

![](../images/20261011_dbsystem_week6_37.png)

- 한 Table에 있는 Tuple과 다른 Table에 있는 Tuple의 조합을 만들 건데 join condition인 c를 만족하는 결과만 조합으로 인정하여 넣겠다.
- 결과는 CARTESIAN 후 SELECT한 결과와 같다.
- Join Condition은 여러 condition을 AND로 묶을 수 있음.
    - 세타는 \{ = , \< , ≤ , \> , ≥ , ≠ \} 중 하나를 의미함.
    - 그래서 세타 조인

#### EQUIJOIN Operation

![](../images/20261011_dbsystem_week6_38.png)

- THETA JOIN 중 특수한 상황을 EQUIJOIN이라고 함.
- condition 즉 세타가 “ = “ 을 사용하는 경우 EQUIJOIN이라고 함.
- result 결과에는 condition에 사용하는 attribute의 value가 같은 값이 나올 수 밖에 없음 → 뭔가 이상하지? → 한 tuple에 같은 속성이고 값이 같은게 있으니까
