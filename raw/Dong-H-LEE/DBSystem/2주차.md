- DBMS(Database Management System)
    - “프로그램”의 집합이다.(즉, DBMS는 Software라는 소리)
    - 사용자가 “매우 쉽게” database를 만들고 관리하게 해주는 그런 software임
- Database System : DBMS(Software) + Database(Data)

정리하면

> Database : Data의 집합

> DBMS : Database를 관리하기 위한 Software

> Database System : DBMS + Database

#### Database System의 구조

![](../images/dbsystem_week2_05.png)

- 우측 하단 Stored Database에 Database가 저장되고 저장된 것을 User-Data라고 부름
- 좌측 하단 Stored Database Definition에 Meta-Data가 저장됨.
    - Meta-Data : User-Data를 관리하기 위해서 DBMS가 필요로 하는 Data
    - ex) User-Data의 갯수, Data 각각의 길이 등
- DBMS Software
    - Storage Engine : User-Data와 Meta-Data를 관리하는 부분
    - SQL(Query) Engine : 사용자가 Storage Engine을 이해하고 프로그램을 짜기 어렵기 때문에 간단한 interface를 통해 단순한 명령어로 사용자가 DBMS를 관리 할 수 있도록 하는 부분
    - DBMS에서는 사용자의 데이터를 저장하고 검색하는 등의 기능을 제공한다.
- Application Programs/Queries : 자기 고유의 코드와 DBMS를 부르는 코드 2개로 나누어진다. → 이것을 Database System에 포함되냐 안되냐는 논란의 여지가 있음.

#### Database의 특성

![](../images/dbsystem_week2_06.png)

- 자기 자신을 기술함 → Database의 구조
- Meta-data
    - 자기가 저장하는 Database의 구조적인 특성에 대한 정보

#### Program과 Database 간의 단절

![](../images/dbsystem_week2_07.png)

- Program과 Data는 단절되어 있다.
    - Data의 변경은 program에 영향을 주지 않는다.
    - Self-describing하는 Database의 특징으로 인해 이것이 가능함.
    - 만약, 사용자 data가 바뀐다면 self-describing에 의해 meta data가 변경되는 것이지 program은 변경되지 않는다.
    - self-describing이 아니라 meta-data가 program의 코드에 저장되어 있었다면 사용자 data의 변경에 따라 해당 코드를 찾아서 변경해야하기 때문에 매우 귀찮아짐.

- 즉, Meta-data로 인해서 self-describing nature가 있다. 이것으로 인해 program은 자주 바뀌는 data에 큰 영향을 받지 않는 장점이 생긴다.

#### DBMS 특징들

![](../images/dbsystem_week2_14.png)

- Redundancy : 같은 data가 2개 이상의 버전을 가지는 것.(2개 이상의 location에 저장되는 것)
    - 공간이 낭비될 수 있음
    - data의 일관성이 떨어질 수 있다.(data 수정 시 하나만 수정된다면)
- DBMS는 이러한 Redundancy를 control해서 문제를 최소화 함.

![](../images/dbsystem_week2_15.png)

- 권한이 없는 접속을 통제함.
- 즉, DBMS는 권한에 의해서 control 되는 소프트웨어이다.

![](../images/dbsystem_week2_16.png)

- Program의 종료와 관계없이 데이터를 지속적으로 남겨준다.
    - 데이터를 main이 아니라 disk에 저장하기 때문에 가능하다.

![](../images/dbsystem_week2_17.png)

- Database를 접근하는 것에 있어서 다양한 방법이 있음.
- 즉, 사용자의 Knowledge 수준에 따라서 access 방법을 다양하게 제공함.

![](../images/dbsystem_week2_18.png)

- entity 간의 관계를 표현하는 다양한 방식을 제공함
    - 이를 통해 실세계의 관계 표현을 조금 더 정확하게 표현할 수 있게 됨.

![](../images/dbsystem_week2_19.png)

- Integrity(무결성) : 우리가 저장하는 database는 결함이 없어야함. 즉, 데이터가 그 조건을 만족해야 integrity가 만족됨. → 어떤 조건..?
- 즉, DBMS는 integrity constraints을 정의할 수 있어야함.
- 또한, DBMS는 integrity constraints 만족 유무를 위해 검증을 하는 기능도 있어야함.

## 실습

![](../images/dbsystem_week2_24.png)

- Indexing이란?
    - “검색이 자주 발생하는 열”을 미리 정렬하는 행위..

        → 자주 검색되는 column의 값들을 미리 정렬

        → 원본 행을 가리키는 Pointer(key-value)를 만들어 빠르게 찾을 수 있게 함.
    - Indexing을 통해 DB 검색을 storage가 아닌 memory space에서 수행 가능함. → 더 빠름
    - 단점 :  삽입 및 삭제의 효율이 낮아짐

        → But, 삽입 및 삭제보다는 검색의 빈도가 훨씬 높음.

![](../images/dbsystem_week2_25.png)

- B+ tree는 DB Indexing에 필요하 인덱스를 효율적으로 저장할 수 있는 구조

#### B+ tree란?

![](../images/dbsystem_week2_26.png)

- B+ tree는 leaf node에서 Pointer로 연결이 되어 있음.
- Pointer로 이어줌으로서 Range Search가 가능함 (예를 들어, 2번부터 6번까지 찾고 싶다 등)
- B tree는 하나하나 각 노드가 data로 이루어져있기 때문에 2번부터 6번까지 하나하나 검색해야함.

## 과제

![](../images/dbsystem_week2_27.png)

- B+ tree : Non-leaf node와 Leaf node 2가지 정도로 나누고 있음.
- m : 키의 갯수
- p = 왼쪽으로 뻗어 나가는 Pointer 갯수 만큼 \<key, left_child_node\> pair인 배열
- r = 오른쪽 자식 노드의 주소(모든 노드는 하나의 오른쪽 자식 노드 제외 모두 왼쪽 자식인거임)
- 루트 노드는 실 데이터가 저장되어 있지 않음

![](../images/dbsystem_week2_28.png)

![](../images/dbsystem_week2_29.png)

- leaf-node의 p에는 \<key, value\>가 들어간다. 즉, 왼쪽 자식 노드의 pointer가 아니라 실제 값 저장.
- leaf-node의 r에는 다음 노드의 헤드를 가리키는 포인터.(링크드 리스트 구조라고 생각하면 됨)
