- 새로운 relation을 만드는 것.
  - Table name
  - Attributes( 속성 이름 - 데이터 타입의 쌍)

- Data types → 저장될 데이터의 타입을 설정
- NOT NULL attribute constraint → NULL 값을 둘 수 없는 attribute를 설정
- DEFAULT clause → 기본값으로 주는 value를 설정

![](../images/20261030_dbsystem_db08_1_09.png)

- PRIMARY KEY clause → 생성하는 Table 내의 여러 attribute 중 어떤 attribute가 PRIMARY KEY인지 알려주는 clause
- UNIQUE clause → Secondary(Candidate key 중 PRIMARY KEY가 되지 못한 것들) Key를 명시하는 clause

![](../images/20261030_dbsystem_db08_1_10.png)

- FOREIGN KEY clause → Foreign key를 명시하기 위해서 사용됨.
- Actions → referential integrity constratint가 깨질 때의 조치들..
  - SET NULL : DELETE 시 NULL로 수정
  - CASCADE : UPDATE 시 자동으로 같이 UPDATE
  - SET DEFAULT : UPDATE시 DEFAULT로..
- Triggers → referential integrity constraint가 깨지는 상황들..
  - ON DELETE : 참조하고 있던 table이 삭제되었을 때
  - ON UPDATE : 참조하고 있던 table이 변경되었을 때

#### Altering Tables

→ table 안에 있는 tuple에 대한 변경이 아닌 schema의 변경을 뜻함.

![](../images/20261030_dbsystem_db08_1_24.png)

- Attribute(Column)을 추가하거나 삭제하는 경우
- 존재하던 Attribute을 수정하는 경우
- Constraint을 추가하거나 삭제하는 경우

![](../images/20261030_dbsystem_db08_1_25.png)

- ALTER TABLE \{TABLE\_NAME\}

  \{OPTION\} COLUMN \{Column\_name\} \{CHANGE\_TO\}

- ALTER TABLE \{TABLE\_NAME\}

  \{OPTION\} CONSTRAINT \{Constraint\_Name\}

- Options
  - ADD
  - DROP
  - ALTER

#### SELECT QUERY BASICS

→ 여기서부터는 DML에 대한 내용

→ Instance를 다루는 것.

![](../images/20261030_dbsystem_db08_1_26.png)

- SELECT : Database로 부터 우리가 원하는 정보를 검색하는 하나의 기본 statement
- \*\*주의 : Algebra에서 본 SELECT와는 다른 것임.

  → Algebra에서는 하나의 table에서 우리가 원하는 tuple을 골라내는 연산이었음.

  → 다만, SQL에서의 SELECT는 Algebra에서의 SELECT,PROJECT,JOIN이 다 합쳐진 연산

![](../images/20261030_dbsystem_db08_1_27.png)

- SQL에서는 하나의 table 내에 모든 attribute value가 똑같은 tuple의 중복을 허용함.
- 즉, SQL에서는 table을 tuple들의 set으로 간주하지 않는다.
- 단, DISTINCT Clause를 사용하면 중복을 막을 수 있다.

#### SQL의 기본적인 형태

![](../images/20261030_dbsystem_db08_1_28.png)

- SELECT \<attribute list>  
  FROM \<table list>  
  WHERE \<condition>
- FROM에 있는 table에서 WHERE에 맞는 tuple들의 SELECT의 attribute value만 보여줘.
