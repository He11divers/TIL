#### Normalization

![](../images/20261124_dbsystem_db13_03.png)

- Normal Forms  
  → 바람직한 Relation의 형태에 대해 정의한 것.
- Normalization  
  → 바람직하지 않은 형태의 Relation을 잘게 쪼개서 각각이 바람직한 형태가 되도록 하는 것.

![](../images/20261124_dbsystem_db13_04.png)

- 바람직한 Relation이 가져야만 하는 특성들  
  → Normalization을 하면서 아래 2개의 특성들을 유지해야함을 명심해야한다.

  1. Lossless join property
  2. Dependency preservation property

#### Prime Attribute

![](../images/20261124_dbsystem_db13_05.png)

- 어떤 Relation Schema R에 속하는 Attribute 중 Candidate Key의 일부가 되는 Attribute.  
  → Candidate Key에 속하는 각 Attribute는 Prime Attribute임.

#### First Normal Form(1NF)

![](../images/20261124_dbsystem_db13_06.png)

- Table에 존재하는 각각의 Attirbute에 대한 Value들이 Single Atomic Value여야 함.  
  → 각 Attribute Value는 주어진 Domain 내에 속하는 하나의 Value만을 가져야함.  
  → Multiple Value를 허용하지 않음.
- 애초에 Relational은 Atomic Value니까 당연한 얘기일듯?

![](../images/20261124_dbsystem_db13_07.png)

- 허용하지 않는 형태
  - Composite Attributes
  - Multi-value Attributes
  - Nested Relations

![](../images/20261124_dbsystem_db13_08.png)

- Dlocations는 ER에서는 Multiple valued였음. → Relation에 저장하기 위해서는 분리해야함 ㅇㅇ

#### Second Normal Form

→ 앞서 배운 FD와 관련된 내용

![](../images/20261124_dbsystem_db13_09.png)

- Full functional dependency
  - X → Y를 만족하는 FD에서 X에 속한 하나의 Attribute A를 제거했을 때 FD가 유지되지 않는 X → Y일 때 Full FD라고 함.
- Partial functional dependency
  - X → Y를 만족하는 X에서 A를 제거해도 X → Y가 유지될 때 Partial FD라고 함.

![](../images/20261124_dbsystem_db13_10.png)

- \{ Ssn, Pnumber \} → Hours에서 Pnumber 혹은 Ssn 중 하나를 제거한다면 유지되지 않음→ Full

![](../images/20261124_dbsystem_db13_11.png)

- \{ Ssn, Pnumber \} → Ename에서 Pnumber를 제거해도 Ssn → Ename이 유지됨 → Partial
- 근데 Ssn을 빼면 hold 되지 않음.. → X에 속한 A 중 어떠한 하나를 뺐을 때 하나라도 유지된다면 Partial?

![](../images/20261124_dbsystem_db13_12.png)

- 어떤 Table Schema R이 2NF를 만족한다  
  = R에 속하는 모든 nonprime attribute A는 R의 Candidate Key에 대해 Fully FD 한다.
- Nonprime Attribute A가 R의 Candidate Key에 대해서 Partial FD라면 2NF에 속하지 않음.

![](../images/20261124_dbsystem_db13_13.png)

- Candidate Key = \{ Property\_id#, \{ County\_name, Lot# \}
- Proterty\_id#은 Primary Key로서 다른 Attribute을 functionally dependent on 시키고 있음.
- Candidate Key 집합도 Proterty\_id#를 포함한 다른 모든 Attribute들을 함수적으로 종속시킴.
- County\_name → Tax\_rate
- Area → Price
- \{ County\_name, Lot# \} → Tax\_rate에서 Lot#을 빼도 FD를 만족하기에 Partial FD임.
- 따라서 LOTS는 2NF를 만족하지 않음.
- 이 Table에는 County\_name과 Lot# 동시에 같은 instance는 없다. 하지만, County\_name이 같은 instance는 존재함.
- 또한 County\_name → Tax\_rate이기 때문에 이 Table의 instance는 \{County\_name, Tax\_rate\}이 같은 애들이 많이 나옴 → 중복

![](../images/20261124_dbsystem_db13_14.png)

- LOTS를 Normalization 하기 위해 LOTS1과 LOTS2로 나눠야 함.
- LOTS1에서 Tax\_rate을 제거하여 Partial FD가 된 이유를 제거

![](../images/20261124_dbsystem_db13_15.png)

- 제거한 Tax\_rate와 그것을 함수적으로 종속 시키는 County\_name을 Attribute로 가지는 LOTS2를 생성.
- County\_name은 LOTS2에서 Foreign Key

![](../images/20261124_dbsystem_db13_16.png)

- 1NF을 만족하는 Relation이라도 2NF를 만족하는 여러 개의 Relation으로 분할할 수 있다.  
  → 이것을 Normalization이라고 부름.

#### Third Normal Form(3NF)

![](../images/20261124_dbsystem_db13_17.png)

- Table에 존재하는 모든 Functional Dependency(X → A)에 대해서도 다음과 같은 조건 둘 중의 하나를 만족한다. → Table에 존재하는 FD 중 하나라도 아래 조건을 둘 다 만족하지 않는다면 3NF를 만족 x
  - a. X는 R의 Superkey이다.
  - 2\. A는 R의 Prime Attribute이다. (즉, 어떤 Candidate Key에 속한다.)
- X라는 Attribute 집합에 의해서 A는 Functionally 종속된다.  
  → X가 같은 Tuple들은 A가 같아야함.  
  → 만약 X가 SuperKey라면, X가 같은 2개 이상의 Tuple은 존재하지 않아야 함.  
  → X가 Superkey가 아니라도, A가 prime attribute라면 중복이 생겨도 인정한다.(왜 허용하는 지는 뒤에 설명)

![](../images/20261124_dbsystem_db13_18.png)

- X인 County\_name이 SuperKey니까 3NF에 속함.

![](../images/20261124_dbsystem_db13_19.png)

- FD4에서 X에 속하는 Area는 SuperKey가 아니고, A에 속하는 Price 또한 prime attribute가 아님.
- 따라서, LOTS1은 3NF가 아니다.

![](../images/20261124_dbsystem_db13_20.png)

- 3NF로 Normalization 하는 방법
- 2NF처럼 LOST1A 와 LOST1B로 나눔.
- LOTS1A에서 문제가 되던 FD4를 분리(A에 속한 Price를 제거)

![](../images/20261124_dbsystem_db13_21.png)

- FD4에 해당하는 FD를 LOTS1B를 생성하여 decompose

![](../images/20261124_dbsystem_db13_22.png)

- 즉, 문제가 일으켰던 FD4에 해당하는 모든 Attribute을 따로 모아 하나의 Table을 만든다. 또한, FD4의 Right-hand side에 해당하는 Attribute을 제거
- 2NF이면서 3NF을 만족하지 않던 Table에 대해서 분해를 통해 Normalization 가능.

#### Boyce-Codd Normal Form(BCNF)

![](../images/20261124_dbsystem_db13_23.png)

- Table Schema R이 hold하는 모든 FD X → A에 대해서, X는 R의 Superkey이어야 함.
- BCNF를 만족하면 중복되는 Tuple이 없어짐.
- 즉, 3NF의 조건 중 (a)의 조건을 만족하면 BCNF라는 것.

![](../images/20261124_dbsystem_db13_24.png)

- FD5에 의해 BCNF에 속하지 않게 됨.
  - FD5의 X에 해당하는 Area가 SuperKey가 아님.

![](../images/20261124_dbsystem_db13_25.png)

- 뭐 이전의 Normalization과 마찬가지로 문제가 되는 FD의 Attribute를 모아서 새로운 Table을 만든다.

![](../images/20261124_dbsystem_db13_26.png)

- 3NF이지만 BCNF가 아닌 Table은 Normalization을 통해 BCNF로 만들 수 있다.

![](../images/20261124_dbsystem_db13_27.png)
