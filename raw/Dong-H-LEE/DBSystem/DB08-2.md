#### Ambiguous Attribute Names

![](../images/20261102_dbsystem_db08_2_07.png)

- SQL에서는 같은 이름의 attribute를 사용하는 것을 허용함.
- 단, 같은 이름이 같은 table에서 사용될 수는 없음. → 다른 table에서는 사용될 수 있다.
- attribute name 앞에 relation name을 써서 ambiguous를 제거함.

![](../images/20261102_dbsystem_db08_2_08.png)

- ex) DEPARTMENT.Dnumber와 EMPLOYEE.Dnumber 처럼 attribute name 앞에 relation name을 적음으로서 어느 Table에 있는 Dnumber인지 구별함.

#### Table Aliases

→ Query 내에서 어느 table의 별칭을 짓는 것

![](../images/20261102_dbsystem_db08_2_09.png)

- **`FROM`** 절에서 **`AS`**&#xB97C; 사용해서 설정 가능.
- Q8에서는 recursive relationship을 참고하는 SQL이니까 aliasing을 통해서 각각 다른 역할을 하는 하나의 table을 구별함.

![](../images/20261102_dbsystem_db08_2_10.png)

- Aliasing은 table명 뿐 아니라 attribute name도 바꿀 수 있음.
- Example에서 포인트는 FROM 절을 통해 E를 aliasing하며 attribute name도 aliasing하였으니 SELECT에서도 aliasing을 사용한다.  
  → aliasing은 이름을 완전 바꾸는 것이 아니니까 기존 이름을 사용해도 되나?

#### Missing WHERE Clause

![](../images/20261102_dbsystem_db08_2_11.png)

- WHERE 절이 없다는 것은 조건이 없다는 의미. → FROM 절에 존재하는 모든 tuple이 대상임.

![](../images/20261102_dbsystem_db08_2_12.png)

- Q9 : EMPLOYEE table에 있는 모든 tuple에 대해서 Ssn을 보여라
- Q10 : EMPLOYEE와 DEPARTMENT의 CARTESIAN PRODUCT의 결과에서 모든 Ssn, Dname을 보여라
- Algebra에서 배웠듯 CARTESIAN 하나만으로는 별다른 의미를 찾을 수 없음 → 거의 사용되지 않는다. 하지만 이런 것도 있다는 것을 알아두자.

#### Tables as Sets

![](../images/20261102_dbsystem_db08_2_14.png)

- SQL은 query result 내에서 중복된 tuple을 자동적으로 제거하지 않음.
- `DISTINCT` 키워드를 사용해서 중복된 tuple을 제거할 수 있음. → 3개가 중복된다면 1개는 제거되고 2개는 남음

![](../images/20261102_dbsystem_db08_2_15.png)

- Q11 : 모든 EMPLOYEE에 대해서 Salary를 보여라. (ALL이니까 중복된 tuple도 모두 보임.)
- Q11A : 모든 EMPLOYEE에 대해서 Salary를 보여라.(DISTINCT니까 중복된 tuple들 사이 하나만 남김.)
- SQL의 Default는 ALL임. 필요하다면 DISTINCT를 사용한다.

![](../images/20261102_dbsystem_db08_2_16.png)

- SET Operation의 결과는 자동으로 중복을 제거함.
- SET Operation의 결과는 Set임.
