#### **논리 연산에서의 and와 not**

![](../images/20260908_system_programming_bits_06.png)

- && , \|\|, !로 사용함.(비트 연산에서는 &, \|, \^, \~)
- 비트 연산과는 뭐가 다를까?
- 논리연산은 그냥 변수를 통으로 생각해서 “참” 또는 “거짓”으로만 판단
- 항상 0 또는 1을 반환함
- Early termination : A && B를 사용했을 때 이미 A가 False를 나타낸다면 B를 볼 필요도 없이 0이 반환되기 때문에 B를 실행도 하지 않는 경우.
- !!은 그냥 참 또는 거짓 중 원래의 값을 표현하게 됨.
- p && \*p : 만약 p가 거짓이면 그냥 0, 참이라면 포인터값을 보도록 사용(즉, 포인터 변수의 guard로서 사용하는 경우도 있음)

#### **Shift 연산**

![](../images/20260908_system_programming_bits_07.png)

- Left Shift : 왼쪽으로 밀고 새로 생긴 최우단 공간에 0을 삽입.
- Right Shift : 논리 연산인지 산술 연산인지에 따라 다르니 주의해야함..
    1. Logical Shift(논리 연산) : Left처럼 최좌단 공간에 0을 삽입.
    2. Arithmetic Shife(산술 연산) : 최상위 비트는 부호를 나타내는 비트인 경우가 많음.

        \<최상위 비트에 따른 방법\>

        1. 최상위 비트가 1인 경우 : 1로 채워둔다.
        2. 최상위 비트가 0인 경우 : 0으로 채워둔다.

#### Truncate

![](../images/system_programming_week2_21.png)

- 비트를 줄이는 연산
- 상위 비트를 제거하는 행위(extension의 반대라고 생각하셈)
- Extension의 경우에는 비트가 늘어나는 것이기에 기존의 수를 그대로 표현할 수 있지만, Truncate는 비트가 감소하니까 표현할 수 있는 숫자의 범위가 줄어든다.
- 즉, 기존에 표현할 수 있었던 수를 truncate 후 표현할 수 없어지는 경우가 생김.

![](../images/system_programming_week2_22.png)

> Extension은 기존의 수를 보장해줄 수 있지만, Truncate는 기존의 수를 반드시 보장하지는 못함.

#### Byte를 기록하는 순서..?

![](../images/system_programming_week2_41.png)

- 메모리를 byte\[idx\]로 표현한다면..offset이 순서대로 증가할 것임.
- Big Endian : 시작 주소에 첫번째 값을 저장하는 방법.(가장 큰 byte order가 먼저 저장) → 옛날 컴퓨터들에 사용
    - 저장장치나 인터넷 패킷은 이 방법을 사용함.
- Little Endian : 시작 주소에 가장 마지막 값을 저장하는 방법.(위 사진에서 78을 먼저 저장하는 방법) (메모리 주소 중 가장 작은 위치에 byte order가 가장 낮은 정보가 저장됨)→ 우리가 사용하는 컴퓨터는 Little Endian을 사용함.
    - 우리는 시작 주소부터 기억하고 offset이 나아가는 방향으로 기억하지만
    - 예를 들어 1000과 10을 더할 때 가장 끝자리를 먼저 저장하면 연산이 쉬워진다고 함..
