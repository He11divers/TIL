#### Floating Point Representation

→ IEEE는 그럼 어떤 식으로 실수 표현을 보장했는가

![](../images/system_programming_week3_07.png)

![](../images/system_programming_week3_08.png)

- s : sign bit(부호 비트)
- M : significand(유효 숫자)
- E : Exponent(order)
- Encoding
    - bit의 위치는 대소 비교에 가장 크게 영향을 미치는 순으로 들어간다고 생각하면 됨.
    - MSB에는 sign bit가 들어감 → 대소 비교에 가장 큰 영향을 미치는 bit
    - sign bit 이후에는 exponent(E)가 들어감 → 2\^13에서 13 중 bias를 뺀 숫자가 들어감
    - 이후 frac field에는 M이 들어감 → 단, M이랑 동일한 숫자가 들어가는 것은 아님.\
      → 유효 숫자를 정규화하지 않는다면 order를 가지고 비교하는 것이 불가능\
      → M을 정규화하는데 2진수에서는 1.xxxxx의 꼴이기 때문에\
      → frac field는 M을 정규화한 부분에서 fraction(소수 부분)만 대입

#### Precision Options

![](../images/system_programming_week3_09.png)

- 32 bit format → 대략 7자리 수의 10진수를 표현할 수 있음
    - sign bit : 1비트
    - exp : 8비트
    - frac : 23비트
- 64 bit format → 대략 16자리 수의 10진수를 표현할 수 있음
    - sign bit : 1비트
    - exp : 11비트
    - frac : 52비트
- half precision(16비트)
- quad precision(128비트)

    - 8개가 모두 1 → special(유효 숫자가 너무 커서 정규화 시키지 못하는 상황)
    - normalized

            - Double precision : 1023

#### Denormalized Values

→ exp field가 000…0인 경우

![](../images/system_programming_week3_13.png)

- 유효숫자 범위 → 0 \~ 255 → -127 \~ 128까지 표현 가능 → -127, 128은 따로 처리 → -126 \~ 127
- -127 → exp = 000…0
- Exponent Value : E = 1 - Bias(-126 or -1022)
- 기억해야 하는 부분
    1. exp 필드가 000…0이기 때문에 더 뺄 수가 없음 → normalize가 불가능한 영역
    2. normalize를 하지 못했기에 1.xxx가 아니라 0.xxxx를 나타냄
    3. sign, exp, frac이 모두 0인 경우 → 0을 나타냄(정수와 같이 IEEE 실수 표현에도 all 0은 0임)
    4. sign만 1이고 나머지 0이면 → - 0을 나타냄
    5. **IEEE에서는 0과 -0 2가지가 있음**

#### Special Values

![](../images/system_programming_week3_14.png)

→ exp field가 111…1인 경우

- case 1 : exp field = 111…1 , frac field = 000…0 → infinity(upper bound)
    - infinity보다 1 비트라도 큰 경우 : NaN(Not a Number)로 처리
- case 2 : sqrt(-1), infinity 끼리의 연산 etc.. → NaN으로 처리

#### C float Decoding Example

![](../images/system_programming_week3_15.png)

- 0xC0A00000 → 우선 binary로 표현
- 1100 0000 1010 0000 0000 0000 0000 0000
- sign bit : 1, exp : 1000 0001, frac : 010 0000 0000 0000 0000 0000
- E : exp - bias = 129 - 127 = 2
- S = 1 → 음수
- M = 1.010 0000 0000 0000 0000 0000 = 1 + 1/4 = 1.25
- v = (-1)\^1 \* 1.25 \* 2\^2 = -5

![](../images/system_programming_week3_16.png)

- 0x001C0000
- 0000 0000 0001 1100 0000 0000 0000 0000
- exp → denormalized
- E = -126
- S = 0
- M = 0.001 1100 0000 0000 0000 0000 = 1/8 + 1/16 + 1/32 = 7/32 = 7\*2\^-5
- v = (-1)\^0 \* 7\*2\^-5 \* 2\^-126 = 7 \* 2\^-131

#### Floating Point Operations : Basic Idea

![](../images/system_programming_week3_24.png)

- IEEE 부동 소수(FP) 덧셈 혹은 곱셈에 대해서는 Round 처리가 들어감.(근삿값 처리)
- Integer와 FP에 대해서 덧셈 또는 곱셈 연산이 다르게 적용될 수 있음. → 다른 하드웨어가 사용됨
- FP 연산에는 overflow, underflow가 없음 → 대소비교는 바뀌지 않지만 round로 인해 결과값은 다를 수 있음

#### Rounding

![](../images/system_programming_week3_25.png)

- Towards Zero(절댓값을 기준으로 내림)
- Round down(내림)
- Round up(올림)
- Nearest Even(기본적으로 사용됨) → 반올림이지만 우리가 사용하는 반올림과는 조금 다름
    - 두 수의 딱 중간 ex) 1.5 → 두 수 중 짝수 쪽으로 이동한다. ⇒ -1.50 → -2 / 2.50 → 2
    - 1.50 → 2 / 2.50 → 2 / 1.50과 2.50의 평균은 2가 됨 ⇒ 우리가 알고 있던 반올림과는 조금 다름.

#### Rounding

→ HardWare 표현

![](../images/system_programming_week3_28.png)

- Hardware에서 rounding을 사용하려면 비트를 임시로 저장할 수 있는 추가 저장 공간이 필요함. → 1\~2bit보다는 더 많은 bit가 필요함 → 더 많은 bit = 값이 더 나감
- 하지만, 컴퓨터에서는 단 2개의 bit만 사용해서 Rounding을 하는 trick을 사용함
- 위 사진에서 빨간색 R 비트와 X 비트를 사용
- HalfWay → R이 1이고 나머지 X가 모두 0일 때
- Incr? → 올림 or 내림
- 3번째와 4번째 2진수는 둘 다 halfway 이것보다 작으면 무조건 내림 크면 무조건 올림 / halfway에서는 Nearest Even

#### C언어에서의 FP 사용 시 주의점

- C언어에서는 float와 double 2개의 타입으로 실수를 표현함
- Type Casting
    - double/float → int
        1. 표현 범위가 줄기 때문에 truncate가 일어날 수 있음.(ex 소숫점 부분)
        2. truncate는 toward zero와 비슷한 연산으로 생각할 수 있음
    - int → double
        1. 표현 범위가 늘기 때문에 truncate와 같은 문제가 생기지는 않음
        2. double이 64비트이고 int가 32비트라면 fraction 안에 그대로 표현 가능함
    - int → flaot
        1. single fraction이면 32비트 내에 fraction이 23비트인데 23비트로 int가 표현이 된다면 문제가 없지만 그 이상이 나온다면 rounding이 들어감
