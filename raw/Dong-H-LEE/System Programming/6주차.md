#### Managing Local Data

→ caller , callee의 독립적인 context 사용을 위한 stack 관리법

![](../images/20261014_system_programming_week6_13.png)

- 각각의 함수는(특히 재귀함수) 독립적인 context를 사용해야함. → 이때 stack을 사용
- 이때 각각의 함수의 독립적인 context가 저장된 stack 사이 사이를 Frame이라고 함.

![](../images/20261014_system_programming_week6_14.png)

![](../images/20261014_system_programming_week6_15.png)

- stack frame에서는 아직 종료되지 않은 함수의 context가 저장되어 있음.
- stack frame을 표현할 때 %rsp 하나의 reg만 사용해서 표현할 수 있음.(%rbp가 optional인 이유)

    → stack frame의 크기는 보통 compiler에 의해서 정해짐.

    → 결정된 크기에 따라서 %rsp를 일정 상수만큼 늘림. 그럼 Frame 크기만 알면 rbp 없어도 시작 위치를 유추할 수 있다.

- rbp를 사용하지 않을 때 2가지 장점이 있음.
    1. stack frame 시작 시 rbp를 사용하면 2개의 reg를 모두 update 해야함.
    2. rbp를 사용하지 않아서 save 된 reg 하나를 callee 함수의 지역변수를 저장하는데 활용할 수 있음.
- 함수를 호출할 때 stack을 할당하는 코드를 “Set-up” 코드라고 함.
- 함수 수행을 마치고 return할 때 stack을 해제하는 코드를 “Finish” 코드라고 함.

#### Register Backup을 위한 공간

![](../images/20261014_system_programming_week6_24.png)

![](../images/20261014_system_programming_week6_25.png)

- Caller-saved → caller가 “callee 전용 reg”를 사용한다.
    - caller가 callee 전용 reg를 사용하게 된다면 반드시 백업본을 만들어놔야한다.
- Callee-saved → callee가 “caller 전용 reg”를 사용한다.
    - callee가 caller 전용 reg를 사용하게 된다면 반드시 백업본을 만들어놔야한다.
- 따로 약속을 정하지 않는다면 callee or caller는 이 reg가 사용되고 있는지 아닌지에 대한 정보조차 모르기 때문에 항상 백업을 하게 될 수도 있음. → 그러면 메모리 및 연산의 낭비가 일어남.
- 따라서 caller가 사용할 reg, callee가 사용할 reg를 나눠서 불필요하게 상대에게 할당된 reg를 사용하게 될 경우는 백업을 만드는 식으로 convention을 정함.
