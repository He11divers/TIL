#### Condition Codes

- 이전 연산 instruction의 수행 결과에 따라서 자동으로 생성됨.
- CF(Carry Flag), SF(Sign Flag), ZF(Zero Flag), OF(Overflow Flag) 4가지의 reg가 존재함.
- 관련 event가 발생했다면 1 / 발생하지 않았다면 0

ex) addq src, dest ↔ t = a + b

![](../images/20261013_system_programming_week5_01.png)

CF set : (unsigned)두 레지스터의 연산 후 비트의 overflow가 일어나서 carry가 발생했을 때 1

ZF set : 두 연산의 결과가 0일 때 1

SF set : 연산 후 MSB bit(부호 비트)가 set이 되었을 때 1

OF set : 2개의 값을 signed value로 봤을 때 양수 2개를 더했는데 음수, 음수 2개를 더했는데 양수가 나오는 경우 1

\*\* CF와 OF의 차이\*\*

CF는 unsigned의 경우 carry가 발생했을 때

OF는 signed의 경우 overflow가 발생했을 때

ex) cmpq src2, src1

![](../images/20261013_system_programming_week5_02.png)

→ cmpq b ,a  → a - b를 활용해서 수행됨. 하지만 a - b의 연산 결과가 저장되지는 않음.

CF set : a + (-b)로 생각하기 때문에 a \< b인 경우 unsigned에서 carry가 발생하기 때문에 Carry flag를 set해서 가져와야함.

ZF set : a == b인 경우

SF set : a \< b인 경우 → ( a - b) \< 0인 경우

OF set : a + (-b)를 생각했을 때 → a가 양수이고 b가 원래 음수였을 경우 a + (-b)는 양수끼리의 덧셈이라고 생각할 수 있음 → 이때 overflow가 발생할 수 있다.

ex) testq src2, src1

![](../images/20261013_system_programming_week5_03.png)

→ testq b, a인 경우 a & b의 연산과 같이 처리함. → 특정 자리의 bit를 masking하고 싶을 때 사용

ZF set : a와 b의 각 자리의 bit가 하나도 같지 않을 때

SF set : a와 b의 MSB bit가 둘 다 1일 때.

CF set / OF set → overflow가 발생할 일도, carry가 발생할 일도 없음

#### Conditional move의 안좋은 사용

![](../images/20261013_system_programming_week5_12.png)

- Conditional move는 if 또는 else case에 대한 모든 값을 준비해놓고 dest reg에 선택적으로 move하는 방식임
- Expensive Computation
    - 각 case에 대한 값을 준비하는 시간이 오래 걸리는 경우. → 사진의 경우는 함수로 표현되어있는데 함수 연산은 평균적으로 오래 걸림.
    - Caller 함수 입장에서는 Callee의 내부가 얼마나 복잡한지 모르기 때문에 무리해서 연산을 미리 시켜두는 행동을 피한다.
    - 함수 호출 자체에 overhead가 있음.
- Risky Computations
    - 포인터 변수에 대해서 양 case에 대한 모든 값을 준비해야함.
    - p가 0이라면 문제가 없을 것 같지만, conditional move를 사용하게 된다면 p가 0이더라도 준비 과정에서 주소값에 접근하게 됨.

        → p가 0이라 주소가 0인 경우에는 process에서는 잘못된 접근으로 판단하여 프로그램을 중단 시킬 수도 있음.

- Computations with side effects
    - 값을 준비하는 과정에서 side effect가 발생할 수 있는 경우
    - x\*=7을 하게 된다면 x의 값이 update됨.
    - 이후 x+=3을 계산할 때 이미 update된 x 값을 사용하기 때문에 의도와 다른 값이 나옴.

#### Switch Statements

- if-else 같은 경우는 비교 조건들을 판단하기 위해서 O(n)의 연산이 필요
- switch문은 비교 연산들에 대해서 O(1)이 필요 → 그래서 switch가 더 빠름

![](../images/20261013_system_programming_week5_24.png)

![](../images/20261013_system_programming_week5_25.png)

- Switch문이 O(1)의 복잡도가 가능한 이유 → Table 구조 사용
- branch에 따라서 점프할 주소들을 table에 모아놓고 table의 index를 통해서 실제 해당 조건에 따라서 jump 할 주소를 결정하는 방법
- Jump Table에 Jump할 주소를 정해두고, 피연산자에 대한 case도 index로 만들어서 Jump Table에 연결
