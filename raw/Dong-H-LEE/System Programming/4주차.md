#### Intel x86 Processor의 역사

![](../images/20260928_system_programming_week4_02.png)

- Intel Processor는 70년대 중반에 등장 → 50년 동안 컴퓨터 시장을 지배함 → 어떠한 이유가 있겠지? → Backward Compatibility(하위호환) 때문임
- Backward Compactability
    - 무어의 법칙 → 1.5\~2년 주기마다 컴퓨터는 2배 좋아진다라는 법칙이 있었음
    - 좋아지는건 좋은데 너무 비싸짐 → 하위 소프트웨어와의 호환성을 보장하는 장점이 있음
- Complec Instruction Set Computer(CISC)

    ![](../images/20260928_system_programming_week4_03.png)

    - ↔ RISC(Reduced \~\~) → Complex or Reduced의 차이
    - CISC는 필요한 경우 명령어를 등록해서 사용할 수 있음 → 복잡한 연산을 적은 수의 명령어로 사용 가능
    - RISC는 복잡한 연산도 기존에 제공하는 기본 연산을 복합 사용해야함.

![](../images/20260928_system_programming_week4_04.png)

- 하위 호환은 기술 개발에 있어서 상당한 부담이 됨 → 당연하지..
- 그에 대해 고민하던 Intel도 여러 시도를 했지만 실패 → AMD 때문..
- AMD는 Intel 호환 processor에서 실행하는 프로그램을 그대로 실행할 수 있으면서 가격은 더 저렴하게 제공함 → 가성비 야르
- Intel은 8비트 → 16비트 → 32비트로 넘어온 후 64비트로 넘어갈 때는 하위호환을 정리하고 64비트에서 다시 출발하려 했음 → 이때 AMD가 32비트 호환이 가능한 64비트 architecture를 공개함(x86-64)

####  C, assembly, machine code

→ 프로그램 소스 코드가 실행 파일로 바뀌는 과정

![](../images/20260928_system_programming_week4_07.png)

- Architecture → Instruction Set Architecture가 풀네임(ISA) : 컴퓨터(하드웨어)를 동작시키기 위한 명령어 set을 말함.
    - Interface / Design 이라고 볼 수 있음.
- Microarchitecture : architecture를 interface / design이라고 한다면 이를 위한 내부 구현을 말함.
    - ex ) 라이브러리 함수에 사용된 내부 알고리즘 및 지역 변수들. 라이브러리를 실행하는 입장에서는 알 필요 없지만 개발자 및 관리자는 최적화 등을 위해 알아야함.
    - Interface는 동일할 수 있지만 내부 코드의 스키마는 다를 수 있고 이에 따라 성능의 차이가 생길 수 있음
- Code Forms
    - Machine Code : 실제 프로세서에게 전달되어 프로세서가 실행하는 코드 → 줄바꿈 없이 byte의 배열 형태로 나타나져 있음 → 사람이 해석하기는 어려움
        1. Object file  → 컴퓨터가 해석은 할 수 있지만 아직은 실행할 수 없는 중간 단계의 코드
        2. Executable file → 우리가 알고 있는 머신코드의 형태
    - Assembly Code : Machine Code 를 조금 더 사람이 해석하기 편하게 표현함
    - Machine Code와 Assembly Code의 관게는 거의 1 : 1임.

#### Moving Data : movq

![](../images/20260928_system_programming_week4_19.png)

- 실제 레지스터에는 data가 저장되어 있는게 아니라 data가 존재하는 memory에서 data를 가져오는 연산이 필요함(register ↔ register에 대한 연산도 이뤄짐)
- load : memory → register
- store : register → memory
- architecture에 따라서 load / store를 구분하기도 intel에서는 mov 명령어 하나로 처리함
- movq → q는 suffix로서 64비트에 표현된 명령어라는 의미임.(참고로 l은 32비트)
    - movq src dest 의 양식(source → destination)
- a + b의 연산 결과를 c에 저장하고 싶다
    - a를 c에 저장하고
    - c + b의 연산을 진행함
- Immediate → 연산에 레지스터가 아닌 상수를 사용할 때
    - memory에서 register로 data를 가져오는 것은 시간이 오래 걸림
    - immediate를 통해서 자주 사용하는 상수는 따로 저장해둬서 시간 단축 시킴
    - “\$” 표시를 사용해서 표현

#### Address Computation Instruction

![](../images/20260928_system_programming_week4_30.png)

- LEA → Load Effective Address
    - leqa (%rdi, %rdi, 2), %rax → src, dest 존재 → mov와 상당히 비슷
    - 왜 lea와 mov를 구별했을까?
        1. move의 경우 계산된 주소의 메모리에 직접 접근해서 저장된 값을 읽어옴
        2. lea는 계산된 주소 자체를 레지스터에 저장 → 메모리에 접근 x
- 곱셈의 경우
    - 2의 제곱의 형태라면 shift 연산으로 처리 가능
    - 2의 제곱이 아니라면 나눠서 처리
        1. 4 x 3 → 4는 shift / 3은 x + x\*2로 처리
